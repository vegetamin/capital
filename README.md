# Alice Life Capital OS 2.0 — 完整源码仓库

**这是多文件项目源码，不是单页 HTML 打包。** 根目录 `index.html` 为 2.0 网页入口，`css/`、`js/core/`、`js/modules/`、`js/importers/` 包含可编辑源文件。`legacy/capital-main/` 保留从用户旧版压缩包提取的完整源代码，供迁移与参考，**不会自动读取或迁移其中的数据**。

## 部署

1. 把仓库根目录的全部文件上传至 GitHub 仓库（不是只上传 index.html）。
2. Settings → Pages → Deploy from a branch → main / (root)。
3. 页面数据保存在当前浏览器的 IndexedDB 中，GitHub 不托管私有账本。
4. 在数据中心定期导出 JSON 备份，离线安全保存。不要把真实账本和备份提交到公开仓库。

## 2.0 入口模块

- `js/core/state.js`：数据库与状态；使用 IndexedDB。
- `js/core/navigation.js`：导航、页面渲染。
- `js/core/finance.js`：余额、净值、收支统计。
- `js/modules/accounts.js`：账户、余额录入。
- `js/modules/ledger.js`：收入、支出、转账流水。
- `js/modules/consumption.js`：消费分析、分类及预算。
- `js/modules/investment.js`：投资持仓及交易决策。
- `js/modules/policy.js`：政策与预算。
- `js/modules/data-center.js`：JSON备份与恢复。
- `js/importers/qianji.js`：钱迹 Excel/CSV 解析、预览与批次导入。
- `legacy/capital-main/`：原始 2.2.0 网站源代码，含旧版阅读、研究、周报等模块，供迁移参考；不是 2.0 活跃模块。

## 注意事项

- 起始业务数据为空，不会假装历史财务数据已迁移。
- 这套功能代码可以部署，但**不保证金融级正确性/生产验收**；需要用真实交易样本核对计算与导入、恢复。
- 旧版阅读、研究、复盘等功能仍在 `legacy/`，**尚未移植成 2.0 页面**。不能因此称为百分之百旧功能全覆盖。
- 2.0 尚没有自动迁移旧版浏览器 localStorage 的机制。保留原仓库与浏览器数据，迁移前先备份。
- 同一账户同一笔钱迹流水与手工流水，自动去重只能覆盖部分情况，需人工核对。
- 目前采用普通 script 多文件组织，避免依赖安装构建工具，适配静态 GitHub Pages。

## 本地启动

在仓库根目录运行 `python -m http.server 8000`，访问 `http://localhost:8000`。

## 资产账目 Excel 导入（2026-10 更新）

进入「资产账户」→「导入资产账目 Excel」，选择旧版 Alice 的 `账目.xlsx` 或同格式 `.xls` 文件。程序会读取「个人财产」工作表（或首个符合条件的工作表）第一行“日期”以及最后一个有效日期列，识别“灵活取用、定期、投资、债权、负债”下的账户项目。先显示预览，确认后新增账户，不覆盖已有账户与流水。同分类同名、且由该功能导入过的账户会跳过；来自其他来源的同名账户不会自动合并，务必人工核对。

不导入“占比、汇总、所有者权益”等计算行；负债以负余额存储。此导入代表截至所选日期的**账面快照**，不是逐笔历史交易。投资项也只是账面价值，不会自动转换为证券持仓；若原系统已有同一投资持仓，请避免重复计算。导入前请先从数据中心导出 JSON 备份。Excel 在浏览器本地读取，不会上传到 GitHub。


## AI 财务分析（新增）
导航新增“AI 财务分析”，可读取资产/消费导入后的本地已确认记录，提供规则统计、数据质量预警、JSON摘要下载与复制 AI 提示词。可选的真实在线 AI 分析通过 `worker/ai-proxy.js` 单独部署；**禁止将 API Key 放入公开 GitHub 仓库**。具体部署、隐私边界见 `docs/AI_ANALYSIS.md`。


### OpenAI API 页面内连接
AI 财务分析页面现支持手动配置 OpenAI API Key、模型、连接测试及选择性本地保存。默认仅会话存储；长期保存为明文，存在泄露风险，推荐 Cloudflare Worker 私有代理。详见 docs/AI_ANALYSIS.md。


### 多 AI 引擎支持
AI 财务分析现在支持 OpenAI、DeepSeek、通义千问、Kimi、智谱 GLM 及自定义 OpenAI Chat Completions 兼容接口。不同引擎分别管理密钥/模型/API 地址。详细配置见 `docs/AI_ANALYSIS.md`。

## 2026-10 AI 多轮财务对话更新

- 「AI 财务分析」现有连续对话、财务诊断、快捷问题、聊天记录本地保存及导出。
- 每次发送问题时，读取当前选定范围的最新财务摘要；同时将最近最多16条已保存对话作为上下文。摘要默认不发送逐笔消费或商户备注；发送前可展开预览并勾选同意。
- 旧版 Worker 仅实现 `/analyze`。要使用对话功能，**必须将 `worker/ai-proxy.js` 在 Cloudflare Workers 同步替换并部署**，新版增加 `/chat`，原 `/analyze` 保持兼容。现有 DeepSeek Secret、访问口令和 ALLOWED_ORIGIN 可以继续使用。
- Worker 使用 `ALLOWED_ORIGIN` 精确限制来源，同时必须自行设置访问口令和限制使用量；一个由用户手动输入的口令并不等于完善的用户认证。浏览器直连密钥仍有泄露风险。
- 对话文本保存在 `localStorage`，和财务数据库分离，**不会被账户 JSON 备份自动包含**。可在 AI 页面导出对话 JSON 或清空。
- 所有分析是辅助建议，不能代替原始账本核对或自动执行证券交易。

## AI 会话档案（IndexedDB）

- 支持多会话、历史搜索、重命名、删除、重新打开和完整 JSON 导入/导出。
- 自动尝试迁移旧版 `alice_os2_ai_chat_v1` 最近消息；迁移成功前不清除旧记录。
- 每条用户和 AI 消息均保存到独立 IndexedDB `alice_os2_ai_memory`；不再保留32条上限。
- 输入框上限由3000提高到50000字符，Ctrl+Enter发送、Enter换行；过长文本会明确提示，不再静默截断。
- 发送给 AI 的历史仍限制最近12条消息以控制费用和上下文；完整历史保存在本机，但不会自动全部交给模型。
- JSON 备份包含完整会话记录，不包含 AI API Key 或财务账本；请另外备份账本。
- IndexedDB 不是云同步；浏览器清站点数据、隐身模式或更换设备均可能丢失，务必定期导出 JSON。
